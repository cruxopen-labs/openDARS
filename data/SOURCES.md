openTARS source snapshot: `36af670d9df0f211d5b6377505f3311c410d33f8`,

No openTARS files were modified by this project.

## Workloads

`configs/models/` contains the HF `config.json` snapshots from:

- `Qwen/Qwen3-0.6B`
- `Qwen/Qwen3.5-0.8B` (text_config only is executed; no vision workload)
- `google/gemma-3-1b-it`

The platform models openTARS W8A8 lowering, not the original BF16 checkpoint execution.
The original model licenses/terms still apply; no weights are redistributed.
Only the supported three model families are implemented. Arbitrary HF architectures,
Gemma contexts beyond its implemented sliding window, and unequal DeltaNet key/value
head counts are not silently approximated.

`tests/fixtures/opentars_queues.json` was generated by
`tools/dump_opentars_queue.py` using openTARS `qwen_ref` real model configurations,
random seed 0 and real `QwenLowering.chunk` calls. It preserves opcode/control/
epilogue/shape/broadcast/group/stride fields. The GEMM HDR_RSV address is excluded
when comparing semantic IR. It is not used as the workload generator.

Fit uses v3.3 Qwen profile and prefill20 operator counters. Baseline/repeat
and Gemma total cycles are validation only. v3.4 is preserved for provenance,
not mixed into the v3.3 FP32 fit. The one-off Qwen3 t=8 slowdown is excluded
from fit and included in validation. Later decode hashes marked
`golden_verified: null` are not independent numerical correctness evidence.

## Hardware and PPA observations

- `deploy/kv260/README.md`, `rtl/tm_core.sv`: 100 MHz, ARR=0, 128-byte GEMV,
  4-element VPU, 16-lane fast FDOT; original v3.3 104,879 LUT, 903 DSP, 118 BRAM.
- `docs/profiling_v33/README.md`: instrumented 104,967 LUT, 58,724 FF,
  903 DSP, 118 BRAM; profile sums/waits and numerical validation qualifications.
- `docs/ddrbw/ddrbw_board.log`, `ddrbw_250.json`: read-only 12.79 GB/s,
  mixed 3R+1W 9.38 GB/s, writes 9.84 GB/s. `ddrbw_300.json` actually ran at
  approximately 333 MHz; it is not used as a 300 MHz point.
- `docs/fp16_state_v34/README.md`: 105,992 LUT, 59,170 FF, 902 DSP, 118 BRAM.
- v3.4 Vivado power estimate: total 4.443 W, dynamic 4.131 W, static 0.312 W,
  PS8 2.435 W. This is not measured board power.
- `docs/project_history.md`: no-array LUT saving about 12k; 16x8 array ~133k LUT,
  16x16 ~175k. These historical implementations are not controlled per-unit
  characterization points and are not treated as such.

The PPA function anchors the baseline totals. Its parameter slopes are explicit
engineering priors, not a fitted per-unit area breakdown. ASIC density/power
constants are illustrative, uncalibrated assumptions. Re-synthesis, timing and
power measurements are required for a selected design.
